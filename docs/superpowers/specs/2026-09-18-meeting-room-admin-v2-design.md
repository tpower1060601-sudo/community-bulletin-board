# 會議室預約管理後台改版設計（v2）

日期：2026-09-18

本文件是對 `docs/superpowers/specs/2026-09-18-meeting-room-board-design.md`（已實作完成並上線）的**修訂**。原設計的「5 台門口螢幕顯示邏輯」（`shared/roomBoard.js`）本身不變，只有**入口資料夾命名**跟著本次改版一起調整；**管理後台的會議室預約分頁**則有實質改版。

## 背景

原本的管理後台會議室預約分頁上線後，使用者反饋跟他原本設想的落差：

1. 房間清單維護表格佔用太多畫面空間，但房間資料其實已經固定、不常變動
2. 缺少「整月總覽」——原本只能選單一天看當天預約，無法一眼看出整月哪幾天忙、哪幾天空
3. 沒有用顏色區分 5 間會議室，總表上看不出「A 會議室」跟「B1 會議室」誰在用哪個時段
4. 新增預約沒有「業戶別」欄位（承租的公司/住戶）、沒有「是否已繳費」的追蹤與警示
5. 5 個入口網頁資料夾命名（`room-a`~`room-e`）跟舊系統既有的 `room01`~`room05` 命名不一致，換螢幕網址時容易對錯房間

## 目標

- 會議室預約分頁改為「月曆總表為主」，一眼看整月疏密狀況
- 5 間會議室用固定顏色區分，月曆格子裡直接看到「房間代碼＋時間」
- 房間清單維護收進收合面板，不再佔用主要畫面空間
- 新增預約時可記錄業戶別（可從既有水牌名錄選，也可手動輸入）、聯絡人、電話、是否已繳費
- 未繳費的預約在總表上要有明顯紅色警示
- 入口資料夾改名為 `room01`~`room05`，對齊舊系統既有命名

## 非目標（本次不做）

- 不做業戶別的獨立資料庫或關聯式管理，`tenant` 就是一個字串欄位，選了水牌名錄的某一列就把公司名稱存進去，跟水牌資料本身不建立關聯（水牌之後改名不會回頭同步更新已存的舊預約）
- 不做「已繳費」金額欄位、收據追蹤、對帳報表，只做一個布林勾選 + 視覺警示
- 5 台門口螢幕的顯示邏輯（狀態計算、輪播、公告）完全不變，這次只改資料夾名稱

## 資料結構變更

### `meetings.bookings` 新增兩個欄位

```js
{
  id: 1758...,
  roomId: 'A',
  date: '2026-09-20',
  startTime: '14:00',
  endTime: '15:30',
  topic: '管委會議',
  person: '王小姐',        // 既有欄位，語意調整為「聯絡人姓名」保持不變
  tenant: '4A - 威傑士國際開發有限公司',  // 新增：業戶別
  paid: false               // 新增：是否已繳費，預設 false
}
```

- `tenant`：字串，可能來自水牌名錄選單（格式 `樓層代碼 - 公司名稱`），也可能是手動輸入的自由文字（例如社區住戶、外部團體）。不做外鍵關聯，就是存一個字串。
- `paid`：布林值。新增預約時預設 `false`（未繳費），需要工作人員在確認收款後主動勾選改為 `true`。
- **既有舊資料（沒有 `paid` 欄位的預約）**：讀取時視為 `paid: true`（已繳費），不會被舊資料突然冒出大量紅框警示。判斷邏輯：`booking.paid !== false`（即 `undefined`/`true` 都算已繳費，只有明確 `false` 才算未繳費）。

### 業戶別下拉選單資料來源

讀取既有 `shared/floorData.js` 的 `DEFAULT_FLOORS`（樓層代碼＋公司名稱），跟目前 `bbs_floors`（管理後台「水牌管理」維護的即時資料，若存在則優先用這份而非預設值）合併成下拉選單選項，格式 `樓層代碼 - 公司名稱`（例如「4A - 威傑士國際開發有限公司」），空白公司名稱的樓層不列入選單。選單最後一個選項固定是「── 其他（手動輸入）──」，選到這個選項時，下拉選單旁邊/下方出現一個文字輸入框讓使用者自己打業戶名稱。

## 管理後台：會議室預約分頁改版

### 版面結構（由上到下）

```
┌─ 會議室預約 ──────────────────────────────────┐
│  [◀]  2026年9月  [▶]              ＋ 新增預約   │
│                                                │
│  日 一 二 三 四 五 六                            │
│  ┌──┬──┬──┬──┬──┬──┬──┐                        │
│  │  │  │A 14-15│  │...每天一個格子...           │
│  └──┴──┴──┴──┴──┴──┴──┘                        │
│  （未繳費的日子該格紅色外框）                     │
│                                                │
│  ── 點選某一天後展開 ──                          │
│  📅 2026/09/20（日）當天預約明細                  │
│  🏢 A會議室（40人）                              │
│    14:00-15:00 管委會議 王小姐 [編輯][刪除]       │
│  🏢 B1會議室（20人）                             │
│    本日無預約                                   │
│  ...（沿用現有房間卡片樣式，每間房固定顯示一張卡）  │
│                                                │
│  ▸ 房間清單設定（收合，預設收起）                 │
└────────────────────────────────────────────────┘
```

### 月曆總表

- 顯示當月完整月曆格線（週日到週六），預設開啟時顯示今天所在的月份
- `[◀]`/`[▶]` 切換上一個月/下一個月，中間顯示「YYYY年M月」
- 每個日期格子：
  - 格子內列出當天每一筆預約的色塊，色塊文字格式「房間代碼 開始時-結束時」（例如「A 14-15」），色塊背景色依房間固定配色
  - 一天預約筆數多時，色塊會往下疊放，格子高度隨內容自動增高（不做「超過幾筆省略」的截斷，畢竟一天最多也就 5 間房各排幾個時段，量體有限）
  - 若當天「任一筆」預約 `paid === false`，整個日期格子加上紅色外框（`2px solid` 紅色），格子背景加淡紅色底色，用來提醒工作人員這天有預約還沒收費
  - 非當月的格子（月曆頭尾補的上/下個月日期）不特別處理，正常顯示但可以稍微淡化顏色
- 點擊任一天的格子，在月曆下方展開「當天預約明細」區塊（沿用既有 `renderBookings()` 的房間卡片樣式：每間房固定一張卡，有預約列出時間/主旨/聯絡人+編輯/刪除按鈕，沒預約顯示「本日無預約」），同時該日期格子要有視覺上「已選取」的標示（例如外框變色或背景加深）
- 「＋ 新增預約」按鈕永遠可見（不用先選日期），點開的新增視窗日期欄位預設帶入「目前展開中的那一天」，若目前沒有展開任何一天則預設今天

### 房間顏色配色（固定 5 色，依房間代碼指定）

| 房間代碼 | 顏色 | Hex |
|---|---|---|
| A | 藍 | `#3b82f6` |
| B | 綠 | `#22c55e` |
| C | 橘 | `#f59e0b` |
| D | 紫 | `#a855f7` |
| E | 紅 | `#ef4444` |

若房間代碼超出 A~E（理論上不會，房間清單固定 5 間），額外房間用灰色 `#6b7280` 當後備色，不報錯。

### 房間清單設定（收合面板）

- 位置移到會議室預約分頁最下方
- 預設收合，只顯示一行標題列「▸ 房間清單設定」，點一下展開/收合（跟現有其他收合區塊的互動模式一致，例如螢幕排版分頁如果已有類似收合元件就沿用同一套 CSS/JS 寫法）
- 展開後內容不變：現有的代碼/房間名稱/容納人數/操作（刪除）表格，「＋ 新增房間」「💾 儲存房間清單」按鈕都保留，邏輯完全不動，只是外層包一層收合容器

## 新增/編輯預約視窗改版

### 版面：兩欄式

```
┌─ 新增預約 ──────────────────────────────┐
│  ┌─ 左欄 ──────┐  ┌─ 右欄 ──────────┐    │
│  │ 業戶別        │  │ 會議室            │   │
│  │ [下拉選單 ▾]  │  │ [下拉選單 ▾]      │   │
│  │ (選「其他」    │  │ 日期              │   │
│  │  才出現手動    │  │ [____/__/__]     │   │
│  │  輸入框)       │  │ 開始時間  結束時間  │   │
│  │ 聯絡人         │  │ [____]   [____]  │   │
│  │ [__________]  │  │ 會議主旨          │   │
│  │ 電話           │  │ [______________] │   │
│  │ [__________]  │  │                  │   │
│  └──────────────┘  └──────────────────┘    │
│                                            │
│  ☐ 已收取場地費（未勾選，總表當天會顯示紅框警示） │
│                                            │
│                          [取消]  [儲存]    │
└──────────────────────────────────────────┘
```

- 左欄：業戶別（下拉選單，選項為水牌名錄 + 「其他（手動輸入）」；選到「其他」時顯示一個文字輸入框）、聯絡人（文字）、電話（文字）
- 右欄：會議室（下拉選單，沿用既有邏輯）、日期、開始時間、結束時間、會議主旨（皆沿用既有邏輯與驗證規則，包含同房間同時段重疊檢查不變）
- 下方新增「已收取場地費」勾選框，新增預約時預設不勾選；編輯既有預約時依 `booking.paid`（讀取時 `undefined` 視為 `true`）回填勾選狀態
- 儲存時把 `tenant`（業戶別最終值：下拉選到的字串，或手動輸入框的字串）跟 `paid`（勾選框狀態）一併存入 `booking` 物件
- 刪除、取消、重疊檢查等既有行為不變

### 當天預約明細卡片的未繳費標示

在月曆下方展開的「當天預約明細」裡，每一筆預約項目（`booking-item`）如果 `paid === false`，要有明顯的紅色標示，例如整個 `booking-item` 加上紅色外框，並在聯絡人資訊旁加註「⚠ 未繳費」文字（紅色字），方便工作人員在明細列表也能一眼看出哪筆還沒收費，不用只靠月曆格子的紅框。

## 入口資料夾改名：`room-a`~`room-e` → `room01`~`room05`

- 已上線的 `renderer/room-a/index.html` ~ `renderer/room-e/index.html` 五個檔案，改名搬移為 `renderer/room01/index.html` ~ `renderer/room05/index.html`
- 對應順序：`room01`=房間代碼 A、`room02`=B、`room03`=C、`room04`=D、`room05`=E（按順序對齊，內容完全比照原本 `room-a`~`room-e` 的內容，檔案內的 `ROOM_ID` 變數值不變，只有資料夾名稱／網址路徑改變）
- 舊資料夾 `renderer/room-a/` ~ `renderer/room-e/` 整個刪除（改名搬移，不是複製一份），避免站上同時存在兩套容易搞混的網址
- `shared/roomBoard.js`、`shared/roomBoardStyle.js`、`shared/api.js`、管理後台程式碼完全不需要更動——這些檔案裡沒有任何地方寫死引用 `room-a`~`room-e` 這個資料夾名稱，房間比對邏輯全部是透過 `ROOM_ID` 全域變數（值仍是 `'A'`~`'E'`），資料夾名稱只是網址路徑，跟程式邏輯無關

## 測試與驗收

- 月曆總表：建立跨越多天、多間房的測試預約資料，確認月曆格子正確顯示每筆預約的房間代碼+時間色塊、顏色跟房間代碼固定對應
- 未繳費紅框：建立一筆 `paid:false` 的預約，確認當天格子跟展開後的預約明細都有紅色警示；確認沒有 `paid` 欄位的舊資料不會被誤判為未繳費
- 月份切換：確認 ◀/▶ 正確切換月份、月曆格線正確對齊星期幾
- 點日期展開：確認點擊日期能正確展開/收合當天明細，且該日期有正確的選取視覺標示
- 新增預約視窗：確認業戶別下拉選單正確列出水牌名錄、選「其他」能手動輸入、「已收取場地費」勾選框存取正確
- 房間清單收合面板：確認預設收起、點擊展開後既有的新增/改名/刪除房間功能都正常運作
- 資料夾改名：確認 5 個新網址 `renderer/room01/` ~ `renderer/room05/` 都能正常顯示對應房間的狀態與公告輪播，且舊的 `renderer/room-a/` ~ `renderer/room-e/` 資料夾已不存在於 repo 中
